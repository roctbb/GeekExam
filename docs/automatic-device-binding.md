# Автоматическая привязка устройства с первого теста

Вход Coding Projects определяет пользователя. Привязку к физическому устройству
подтверждает отдельный HTTPS-запрос браузера к агенту **в сети кабинета**.
Одинаковый внешний IP, единственная сессия пользователя, cookie и отпечаток
браузера не используются как доказательство принадлежности к LAN.

## Протокол

1. GeekExam принимает первый heartbeat владельца попытки. Затем сервер запрашивает
   у Guard одноразовое подтверждение для `(ученик, попытка, клиент браузера, кабинет)`.
   Преподаватель, настроивший кабинет теста, должен сохранять право на этот кабинет.
   Для учителя сохраняется проверка состава учеников кабинета; администратор имеет
   доступ ко всем ученикам. Автопривязка не расширяет состав кабинета.
2. Guard выдаёт до четырёх коротких случайных токенов для настроенных роутеров этого
   кабинета. Срок — 45 секунд. В базе хранится хеш токена. Токен не содержит логина,
   пароля, имени, ответов или клиентского IP.
3. Браузер посылает токен локальному агенту. `credentials: omit`, запрещены редиректы,
   передача cookie Coding Projects/GeekExam/Guard и произвольных сетевых параметров.
4. Агент принимает только HTTPS, точные Host и Origin, заданные ученические подсети.
   IP берётся из TCP-сокета. `X-Forwarded-For` и поля страницы не участвуют в выборе
   устройства. После проверки токена у Guard агент читает свежие Wi-Fi-ассоциации
   и таблицу клиентов роутера и передаёт Guard совпадение IP/MAC/epoch/boot.
5. Guard проверяет машинный ключ именно этого роутера, кабинет, сетевой источник,
   текущие роли, свежесть наблюдения и однозначность устройства. Живая сессия другого
   ученика не перезаписывается. При необходимости создаётся сетевая сессия текущего
   пользователя, как при подтверждённом входе в сеть.
6. GeekExam получает результат по защищённому серверному каналу и проверяет владельца,
   клиента и незавершённость попытки ещё раз. Сетевое ожидание не удерживает блокировки
   попытки и не блокирует сохранение ответов. В журнал добавляется метод `browser_lan_proof`.

После первой привязки исходное устройство попытки не заменяется автоматически.
Другой браузер на том же устройстве может подтвердить его отдельно; другое устройство
создаёт событие для проверки и сохраняет исходную привязку. Переподключение с изменением
сетевой сессии во время активного теста сохраняет историю обрыва; исходный интервал
не затирается новым подтверждением. При необходимости преподаватель уточняет привязку.
Для каждой **новой попытки** выполняется новое автоматическое сетевое подтверждение.

Повтор использованного токена, чужая попытка/вкладка/кабинет, отключённый endpoint,
истёкшая роль, неполный или старый список роутера дают отказ. Нет доказательства —
нет автоматической привязки и нет самостоятельного вывода о списывании.

## Однократная настройка кабинета

1. Обеспечить постоянный LAN-хост агента. Для текущего Mac адрес нужно закрепить
   DHCP-резервированием. В будущем предпочтителен постоянно включённый мини-ПК.
2. Выделить отдельное имя, например `lan-409.guard.geekclass.ru`, и отдельный публично
   доверенный сертификат **только этого имени**. Ключи `exam.geekclass.ru` и Coding Projects
   не копируются. Имя в DNS кабинета направляется на LAN-хост, а не на интернет-сервер.
   При использовании защищённого DNS клиентом нужно проверить, что локальное имя
   действительно разрешается в адрес агента.
3. В локальный `challenger.json` добавить:

```json
{
  "browser_proof": {
    "listen": "192.168.2.123",
    "port": 18766,
    "origin": "https://lan-409.guard.geekclass.ru:18766",
    "student_subnets": ["192.168.2.0/24"],
    "allowed_origins": ["https://exam.geekclass.ru"],
    "tls_cert_file": "/Users/roctbb/.config/geekguard/tls/challenger/fullchain.pem",
    "tls_key_file": "/Users/roctbb/.config/geekguard/tls/challenger/privkey.pem"
  }
}
```

Адрес `listen` — пример, применять только после проверки и резервирования. Запрещены
`0.0.0.0`, loopback, публичный bind, открытие порта в WAN, HTTP и недоверенные сертификаты.
Файл ключа — 0600. ОС хоста должна разрешать входящий HTTPS от ученического сегмента.
Для проверки подключения можно временно добавить `"diagnostics": true` внутрь
`browser_proof`: журнал покажет этапы и известные коды отказа, без токенов,
пользовательских данных, MAC и IP. После настройки диагностику следует отключить.
Listener должен принимать соединения учеников напрямую, без HTTP reverse proxy;
запросы с самого хоста агента отклоняются, чтобы не принять прокси за устройство ученика.
Если агент и ученики в разных VLAN, маршрутизация должна сохранять исходный IP,
а доступ к listener ограничиваться заданными сегментами.

4. В Guard: кабинет → «Роутеры» → «Автопривязка GeekExam». Указать тот же HTTPS-origin
   и включить настройку **после** проверки DNS/TLS/listener. Настройка отдельная для
   каждого роутера. Ни агента, ни сетевых правил она сама по себе не устанавливает.
5. В GeekExam выбрать кабинет теста. Ученики открывают тест обычным образом. Chrome
   может попросить разрешение на обращение к локальной сети; отказ не блокирует ответы,
   но оставляет сетевую привязку неподтверждённой. Проверить Chrome/Safari/Firefox
   на реальных ученических устройствах; разрешения ОС и браузера могут отличаться.

## Сертификат и развёртывание

`guard/deploy/lan-certificate.nginx.conf.example` обслуживает только ACME HTTP-01.
Listener не публикуется в интернете. Certbot обновляет отдельный сертификат на сервере.
После обновления выделенная пара экспортируется в закрытый каталог оператора (0700/0600).
`guard/scripts/refresh_lan_certificate.py` забирает её по существующему проверенному SSH
и проверяет соответствие ключа сертификату до замены файлов. Пример ежедневного
LaunchAgent — `guard/deploy/refresh-lan-certificate.plist.example`.
Агент подхватывает новую пару без перезапуска и смены boot_id.

Для действующей базы Guard перед запуском новой версии создать резервную копию,
затем выполнить `flask --app guard_service:create_app upgrade-browser-proof-schema`.
Добавляются только `local_proof_endpoint` и `browser_proof`, существующие таблицы
не изменяются. Команда идемпотентна. Удаление старых одноразовых подтверждений
старше суток выполняется при выдаче новых; журнал и сведения GeekExam сохраняются.
GeekExam новой миграции для этой функции не требует. Ключ машинного обмена остаётся
независимым от ключей пользовательского входа.

## Практические границы

Это подтверждает источник запроса, наблюдаемый локальным агентом, и помогает находить
переключение сетей и устройств. Оно не доказывает присутствие человека перед экраном,
не определяет все VPN и не защищает от сговора или намеренной ретрансляции запросов
через другое устройство. Для более строгого контроля нужны управляемые устройства
или сетевой доступ с индивидуальными учётными данными/сертификатами.

Проверять реальный сценарий только после настройки LAN: новое устройство без старой
привязки → первый тест → новый тест → мобильные данные → возвращение в Wi-Fi → другое
устройство под тем же логином. Общие сбои по-прежнему отделены от персональных событий.
