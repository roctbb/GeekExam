# Wi-Fi через Coding Projects

Guard использует штатный Captive Portal (Coova-Chilli) KeeneticOS на отдельном ученическом Bridge. WPA-пароль Wi-Fi остаётся паролем сети; персональный вход выполняется в браузере через SSO Coding Projects. Это не WPA Enterprise и не передача паролей Coding Projects в RADIUS.

## Путь входа

1. Подключение к ученическому SSID открывает `https://guard.geekclass.ru/connect/<router_id>`.
2. Guard выполняет существующий SSO с одноразовым state/JWT, сохраняет точный адрес страницы возврата. Параметры UAM (`mac`, `ip`, `userurl`) не используются как идентификатор или адрес возврата.
3. Вошедший пользователь получает одноразовый 45-секундный LAN challenge. Его браузер обращается по HTTPS к агенту. Агент использует фактический TCP peer и свежую Wi-Fi-ассоциацию, а не переданные браузером IP/MAC.
4. Guard создаёт сетевую сессию `codingprojects_portal`. Пользователь, роль, роутер, сегмент и текущая ассоциация проверяются сервером. Живое устройство другого пользователя не перепривязывается автоматически. Ученик с подтверждённым присутствием становится участником кабинета; преподавательские права управления кабинетами этим не выдаются.
5. Действующее исключение устройства даёт полный доступ без персонального входа. Иначе преподаватель/администратор получает полный доступ, ученик — доступ по индивидуальному правилу или режиму кабинета. Без входа доступны сервер учебных сервисов и технические адреса портала.

## Применение

Опциональный `CaptiveEnforcer` работает только с локально указанными `ChilliN` и отдельным `BridgeN` (не Bridge0). Он сверяет конфигурацию, IPv6-маршруты и список активных сессий, запускает вход для разрешённых устройств и выполняет `chilli logout` при отзыве доступа.

В агенте работает LAN-only RADIUS с зависимостью `pyrad==2.4`. UDP привязан к LAN-адресу Mac и принимает пакеты только от IP роутера. Управление роутером и RADIUS через интернет не публикуются. Для каждого входа агент генерирует случайные технические имя/пароль, действующие 12 секунд, проверяет NAS-ID, Calling-Station-ID и PAP/CHAP. CP-пароли и машинный ключ Guard в RADIUS не передаются. Если запрос содержит Message-Authenticator, подпись обязательна к проверке; ответы Access-Accept/Reject всегда подписываются Message-Authenticator. Наследующие запросы без Message-Authenticator допустимы только от локально закреплённого NAS и всё равно требуют случайный технический пароль.

Роутер получает Session-Timeout 30 секунд; работающий агент обновляет разрешение каждые 15 секунд. При остановке Mac последнее разрешение не должно пережить таймер роутера. При потере облака агент не выдаёт новые сессионные права по данным старше 20 секунд. Исключения устройств применяются через тот же механизм, с учётом срока исключения.

Полный статус `applied` появляется после чтения сессий обратно с роутера. Состояние «назначен полный доступ» в UI само по себе не доказывает завершение RADIUS-входа.

## Однократная подготовка

- Резервная копия, отдельный ученический SSID/Bridge, управляющий Mac в другом сегменте.
- Компонент `chilli`, `Chilli0` с `dhcpif Bridge1`, UAM server со своим router_id, локальный адрес RADIUS/NAS-ID и отдельный случайный секрет.
- Walled garden только к TCP 443 сервера учебных сервисов и TCP 18766 LAN-агента. Доступ к другим внутренним устройствам не требуется.
- DNS для LAN HTTPS hostname, действующий отдельный TLS-сертификат и разрешение только нужного origin Guard/GeekExam.
- Новый сегмент зарегистрирован в Guard и в локальном конфиге агента; `captive_portal` включает native driver без экспериментального IPv4 ACL.
- Образ Guard через Git, аддитивная команда `upgrade-network-login-schema`, резервная копия БД перед обновлением.

Обычный вход не означает доказательство отсутствия мобильного интернета или второго устройства. Проверки реального редиректа, входа, ограничения, отзыва и тайм-аута RADIUS должны фиксироваться отдельно от модульных тестов. Разрешение `195.133.49.12:443` охватывает все HTTPS-сервисы на этом сервере.
