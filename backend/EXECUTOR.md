# Backend интеграции с GeekExecutor

Задачи, приватные критерии, файлы, ответы, снимки проверок и результаты
принадлежат GeekExam. Исполнитель использует тот же подписанный API,
что Coding Projects. Контракт интерфейса описан ниже.

## Настройка и миграции

Выполнить `flask --app manage db upgrade`: миграция
`d8a15f9c3b20_executor_storage` добавляет хранилище запусков/файлов после
миграции дробных баллов `c7f04e8b2a19`. Старые ответы не удаляются.

```dotenv
GEEKEXECUTOR_URL=https://executor.example
GEEKEXECUTOR_SOCKET_URL=https://executor.example
GEEKEXECUTOR_SECRET=INDEPENDENT_RANDOM_SECRET_AT_LEAST_32_CHARS
EXECUTOR_CALLBACK_BASE_URL=https://exam.example
EXECUTOR_STORAGE_DIR=/app/executor-data
```

В GeekExecutor зарегистрировать `geekexam` с этим ключом, origin экзамена и
`api_prefix=/api/executor` в `CHECKER_CLIENTS_JSON`; разрешить origin фронтенда
в `SOCKET_ALLOWED_ORIGINS`. `JWT_SECRET` GeekExam остаётся отдельным ключом
входа и не используется для проверок. Backend и worker получают один том
`executor_data` в Compose. Его нужно резервировать вместе с БД. Работают
Celery worker и beat: повторная отправка outbox каждую минуту.

Переход применяется к новым проверкам `ai/docker`. `manual/exact` сохраняют
прежнее поведение. Старый адаптер и `/api/callback/check` удалены.
Проверки идут только через подписанное `/api/executor`; старые сохранённые
ответы и оценки остаются в базе. Перед обновлением завершите старые задания.

## Настройки задачи

`check_config`: `lang`, `allowed_languages`, `submission_modes`
(`text/code/files/project/repository`), `allowed_extensions`, `entrypoint`,
`max_files` (до 100), `max_file_bytes/max_total_bytes` (до 50 MiB).
Для `docker`: `tests` (1..200, `input/expected/hidden/name`, лимит до 30 секунд),
Python, C++ или Brainfuck. Для `ai`: `prompt/private_instructions`,
`reference_answer`, `gpt_model`. Файлы и текст допустимо комбинировать.
`score_step` сохраняет дробные оценки: для тестов исполнитель возвращает
число пройденных, платформа нормализует по замороженному максимуму; AI
получает целую шкалу и явную инструкцию пересчёта. Текущие изменения задания
не меняют шкалу запущенной проверки.

Ответ `Answer.value`: `{mode, text, code, lang, files:[{path,content}]}` либо
`files:[{upload_id,path?}]`. Репозиторий: `mode=repository`,
`repository_url`, необязательный `repository_ref`. Поддерживаются публичные
GitHub-репозитории; платформа фиксирует SHA и сохраняет ZIP и файлы до отправки.
Для проекта используются Python stdlib / C++17, без произвольной сборки
и установки зависимостей. Файлы и пути проверяются до отправки исполнителю.

## API интерфейса

Все ручки требуют сессию и проверяют владельца ответа или роль преподавателя.

| Маршрут | Назначение |
|---|---|
| `GET/POST /api/answers/{id}/files` | Список / multipart `file`, необязательный `path`; вернуть upload ID |
| `GET/DELETE /api/answers/{id}/files/{file}` | Скачать / удалить невыбранный файл черновика, снимки не меняются |
| `PUT /api/answers/{id}` | Сохранить черновик value с upload IDs или редакторскими файлами |
| `POST /api/answers/{id}/check` | Промежуточная проверка, сразу вернуть `executions` |
| `POST /api/attempts/{id}/finish` | Закончить, создать снимки async-ответов, вернуть `executions` |
| `POST /api/answers/{id}/recheck` | Преподавателю: новая проверка, старая оценка сохраняется до результата |
| `GET /api/answers/{id}/execution` | Последний запуск и обновлённая подписка |
| `GET /api/answers/{id}/executions` | История запусков, пагинация по 20 |
| `GET /api/executions/{id}` | Сохранённые исходники, результат, подписка |
| `GET /api/executions/{id}/artifacts/{sha256}` | Разрешённый оригинал исходника/поля отчёта |
| `GET/POST /api/questions/{id}/files` | Преподавателю: файлы условия/шаблоны/материалы проверки |
| `DELETE /api/questions/{id}/files/{file}` | Преподавателю: мягкое удаление, снимки сохраняются |
| `GET /api/attempts/{id}/questions/{question}/files` | Только разрешённые материалы задания и ссылки скачивания |

У файла задания `kind=attachment/starter/resource`, `is_public`, `read_only`,
`include_in_check`. Приватный файл допустим только как attachment, не как
ресурс исполняемой программы. Неизменяемые шаблоны нельзя подменить.
Ученику не выдаются приватные AI-промпты и ввод/эталон/вывод скрытого теста,
включая страницы результатов завершённого экзамена. Преподаватель видит полный
снимок. Оригиналы файлов доступны как downloads; записи файлов не содержат
публичных постоянных URL.

## События и гарантии

Ответы сдачи/проверки и GET попытки содержат `executions` с
`answer_id/question_id/execution_id/subscription`. Существующий защищённый
канал попытки дополнительно выдаёт `execution_created`; прежние
`answer_checked/attempt_finished/attempt_checked` сохраняются.

`subscription` выдаёт URL, namespace `/executions`, token и срок действия.
Браузер подключается прямо к GeekExecutor: Socket.IO `auth.token`,
`transports=['websocket']`, событие `execution_progress`. Оно содержит только
ID, sequence, phase, completed/total; не содержит закрытых данных. При новом
подключении приходит последнее состояние. HTTP polling не требуется;
после completed/error нужно один раз прочитать сохранённый результат платформы.

Промежуточная проверка не выставляет финальный балл. Старый callback не меняет
новый ответ/запуск; повтор одного результата не начисляет баллы повторно,
отличающийся результат получает 409. Исходники и шкала заморожены. Сетевые
сбои повторяются через outbox; ошибка инфраструктуры не заменяет сохранённую
оценку нулём. Большие поля хранятся по SHA-256 и передаются по короткоживущим
подписанным ссылкам только между зарегистрированными origin.

## Проверка

`python -m pytest -q --disable-warnings` — регрессионные и signed API тесты.
`python tests/executor_live_smoke.py --executor-dir /path/to/GeekExecutor`
— настоящий HTTP/Redis/Celery/WebSocket обмен с большим файлом, скрытым тестом
и оценкой 1,5 балла; создаёт только временные БД и хранилища.
Общий Docker/Celery/WebSocket/S3 стенд обеих платформ описан в репозитории
Coding Projects, `docs/executor-qa.md`. Он также проверяет параллельные запуски,
вход администратора и отсутствие старого callback; production-данные не использует.

## Интерфейс сдачи

На странице вопроса и в результатах подключены форматы файлов, вставки кода,
проекта из нескольких файлов, текстового ответа и GitHub. Разрешённые форматы,
язык и лимиты приходят в `submission_config` без промптов и эталонов. Upload
передаёт файлы отдельно; автосохранение хранит ссылки на принадлежащие ответу
артефакты. Во время загрузки переходы между вопросами и завершение блокируются.

`ExecutionResult` показывает неизменяемые исходники, отчёт с фильтрацией
скрытых тестов и историю запусков. Статус поступает напрямую через WebSocket
GeekExecutor. Завершение обновляет сохранённую оценку однократным GET. Списки
результатов обновляются через защищённые комнаты `user_{id}` и `test_{id}`
GeekExam, периодического HTTP polling нет. Перепроверка сохраняет прежние баллы.

Редактор преподавателя поддерживает способы сдачи, языки, расширения, лимиты,
приватные критерии ИИ, эталон, модель, публичность тестов и материалы. Файлы
вопросов сохраняют принадлежность при редактировании благодаря стабильным ID.
Предпросмотр файлов работает локально и не создаёт реальные ответы.
